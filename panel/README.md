# Конфигурация панели Remnawave

Здесь хранится то, что настраивается в панели, а не на сервере:
профили Xray и правила, по которым ноды собираются в каскад.
Установщик (`setup_remnawave_node.sh`) готовит сервер под роль, а
в панели ноду нужно привязать к нужному профилю. Подсказку для
каждой роли скрипт выводит в конце работы.

> Файлы `profiles/*.json` и `../tools/rw_export.py` добавляются
> отдельно. В профилях нет секретов: вместо ключей и UUID стоят
> плейсхолдеры `REPLACE_*`.

## Схема

```
клиент ──443/tcp──▶ entry (РФ) ──NetBird, bridge-in :10443──▶ exit (за рубежом) ──▶ интернет

клиент ──443/tcp, 443/udp (Hysteria2), 8443/tcp──▶ exit-direct ──▶ интернет
```

Прямые подключения к зарубежным нодам почти не работают, поэтому
клиенты ходят через входные ноды в РФ. Исключение — одна нода
`exit-direct` (Финляндия): там прямые подключения и Hysteria2
сохранены.

## Роли и профили

| Роль ноды     | Профиль       | Что в нём                                                               |
|---------------|---------------|-------------------------------------------------------------------------|
| `entry`       | `entry-ru`    | инбаунд `entry-selfsteal` (Reality на `127.0.0.1:10443`), аутбаунды `to-...` на выходы |
| `exit`        | `exit`        | инбаунд `bridge-in` (`:10443`, только через NetBird)                    |
| `exit-direct` | `exit-direct` | инбаунды для прямых подключений и Hysteria2                             |

Reality на `entry` и `exit-direct` берёт сайт-заглушку ноды как
`target`: `127.0.0.1:9443` (`SITE_LOCAL_PORT`). Proxy protocol не
используется, `xver: 0`.

Порт `10443` (`bridge-in`) в UFW не открыт ни на одной ноде. Мост
работает только через NetBird, потому что NetBird ставит свои правила
файрвола раньше UFW.

## Сквады

- `clients` — пользователи сервиса.
- `bridges` — служебные пользователи `_bridge-<выход>`. Входная нода
  авторизуется ими на `bridge-in` выходной ноды через аутбаунд
  `to-<выход>` в профиле `entry-ru`.

## Как добавить ноду

### entry

1. На сервере: `NODE_ROLE=entry`, `NODE_DOMAIN=<домен>`, запустить установщик.
2. Nodes → Management → [+]: адрес — NetBird IP ноды, порт — `NODE_PORT`.
   Профиль `entry-ru`.
3. В инбаунде `entry-selfsteal` добавить `NODE_DOMAIN` в `serverNames`.
4. Создать хост: адрес `NODE_DOMAIN`, SNI `NODE_DOMAIN`, указать явно.

### exit

1. На сервере: `NODE_ROLE=exit`, запустить установщик.
2. Создать ноду с NetBird IP, профиль `exit`.
3. В NetBird переименовать пир в `exit-<страна><номер>`.
4. В профиль `entry-ru` добавить аутбаунд `to-<страна><номер>` на этот пир.
5. Создать служебного пользователя `_bridge-<страна><номер>` в скваде `bridges`.

### exit-direct

1. На сервере: `NODE_ROLE=exit-direct`, `NODE_DOMAIN=<домен>`, запустить установщик.
2. Создать ноду с NetBird IP, профиль `exit-direct`.
3. Создать хосты для прямых подключений.

## Сертификат для Hysteria2 (exit-direct)

Установщик монтирует `/opt/certs` в `remnanode` по пути
`/var/lib/remnawave/configs/xray/ssl`. В профиле указываются:

```
certificateFile: /var/lib/remnawave/configs/xray/ssl/fullchain.pem
keyFile:         /var/lib/remnawave/configs/xray/ssl/privkey.key
```

Важно: в документации Remnawave этот путь описан для контейнера
**панели**. Если такие файлы есть у самой панели, она перед отправкой
конфига на ноду встраивает их содержимое (`certificate`/`key`) вместо
путей. Тогда нода использует сертификат панели, и он не обновляется
после продления на ноде. Чтобы работал сертификат ноды, у контейнера
панели не должно быть файлов по этому пути.

Когда в конфиг попадает путь, Xray перечитывает файлы сам, раз в час
(по умолчанию). Поэтому CertWarden-клиент после продления
перезапускает только `nginx`: перезапуск `remnanode` оборвал бы все
подключения.
